How Smart Match stays safe

  • It never renames, moves, deletes or edits media files or folders. Plex, qBittorrent and other tools that share the same paths are unaffected.
  • Report only is the default. Nothing in Jellyfin changes until an admin clicks Apply, confirms a bulk preview, or explicitly enables auto-apply for a library.
  • Before every write it re-reads the item and aborts on any change: a new provider id, a lock, a different path or an edited title.
  • It writes only the selected provider ids (and the title, when it is still the unedited filename-derived title), then asks Jellyfin for a normal refresh that fills missing metadata. Existing images are never replaced; locked fields stay locked.
  • Ambiguous titles such as The Office without a year are never applied in bulk or automatically.
  • Every change is recorded and can be rolled back while nobody else has edited the same fields.

Jellyfin's own sidecar files

If a library has metadata savers (for example NFO) or Save artwork into media folders enabled, Jellyfin itself writes those files next to the media during any refresh, including one Smart Match requests. Smart Match flags such libraries, blocks unattended auto-apply there until you acknowledge it, and recommends mounting media read-only in Docker.
